# Creating a New Game Server Instance

This document explains how to create a new game server instance using KGSM. If you haven't already, please read [Blueprints 101](blueprints.md) and [Instances 101](instances.md) for foundational knowledge.

---

## Quick Overview

There are three ways to create a new game server instance:

1. **Named Arguments**: Use the `install` command.
2. **Interactive Mode**: Run `kgsm.sh interactive` to use the menu-driven interface.
3. **Manual Instance Creation**: Execute each module manually for full control.

---

## Option 1: Named Arguments

This is the simplest way to create an instance:

```sh
./kgsm.sh install <blueprint> [--install-dir <directory>] [--version <version>] [--name <name>]
```

`create` is an alias for `install` and can be used interchangeably.

### Arguments

- **`<blueprint>`**: The blueprint name (without the `.bp.yaml` extension). KGSM searches user blueprints first, then bundled blueprints. Run `./kgsm.sh blueprints list` to see all available blueprints.
- **`--install-dir <directory>`** *(optional)*: Absolute path where the instance will be installed. If omitted, the value from `default_install_directory` in `config.ini` is used.
- **`--version <version>`** *(optional)*: A specific version to install. If omitted, the latest available version is fetched automatically.
- **`--name <name>`** *(optional)*: Custom name for the instance. If omitted, KGSM generates a unique identifier based on the blueprint name.

### Example

```sh
./kgsm.sh install factorio --install-dir /opt/servers --name factorio-space-age
```

---

## Option 2: Interactive Mode

Launch the interactive menu to install a server through a guided interface:

```sh
./kgsm.sh interactive
```

From the menu, choose the **Install** option. You'll be prompted to:

- Select a blueprint.
- Provide an installation directory (if `default_install_directory` is not set in `config.ini`).
- Provide a version to download (leave empty for "latest").
- Provide an instance identifier (leave empty for "autogenerated").

---

## Option 3: Manual Instance Creation

For advanced users, each step can be executed individually. All modules automatically determine the KGSM installation path and load the configuration without requiring any manual setup.

### Step-by-Step Breakdown

Here's how the command `./kgsm.sh install factorio --install-dir /opt/test` breaks down into its individual steps:

---

### 1. Choose a Blueprint File

List available blueprints to find the one you want:

```sh
./kgsm.sh blueprints list
```

Blueprints are loaded in this priority order:

1. User custom (`blueprints/` in your XDG data directory)
2. Bundled (`blueprints/` in the KGSM install directory)

A user blueprint shadows a bundled one of the same name. (Both are flat
directories of `<name>.bp.yaml` files — the `runtime` field, not the location,
determines native vs. container.)

Run `./kgsm.sh --paths` to see the exact paths for your system.

---

### 2. Ensure the Installation Directory Exists

```sh
./kgsm.sh directories ensure-created /opt/test
```

This creates the top-level installation directory if it doesn't already exist.

---

### 3. Generate an Instance Identifier

```sh
instance=$(./kgsm.sh instances generate-id factorio --name my-factorio-server)
```

This validates that the blueprint exists and produces a unique identifier for the new instance. The `--name` flag is optional — if omitted, a name is auto-generated from the blueprint name.

---

### 4. Create the Instance Working Directory

```sh
working_dir="/opt/test/factorio/${instance}"
./kgsm.sh directories ensure-created "$working_dir"
```

This creates the directory that will hold all of this instance's files.

---

### 5. Link the Instance into KGSM

```sh
./kgsm.sh directories link-instance factorio "$instance" "$working_dir"
```

This creates a symlink from KGSM's internal instances directory to the working directory, allowing KGSM to track the instance regardless of where it is physically installed.

---

### 6. Create the Instance Configuration

```sh
./kgsm.sh instances create factorio --install-dir /opt/test --name "$instance"
```

This generates the instance configuration file (`<instance>.config.ini`) inside the working directory.

---

### 7. Create the Directory Structure

```sh
./kgsm.sh directories create "$instance"
```

This creates the following subdirectories inside the working directory:

- `backups/` — Instance backup files
- `install/` — Game server installation files
- `saves/` — Game save files and world data
- `temp/` — Temporary files during operations
- `logs/` — Instance-specific log files

---

### 8. Generate Instance Files

```sh
./kgsm.sh files create "$instance"
```

This creates the `<instance>.manage.sh` management script. Depending on `config.ini` settings, it may also create:

- UFW firewall rules (if `enable_firewall_management=true`)
- Command shortcuts/symlinks (if `enable_command_shortcuts=true`)

> ⚠️ **Note**: Root permissions are required for UFW integration. KGSM will prompt for a password when needed.

---

### 9. Locate the Instance Management File

The instance is now standalone and does not need KGSM to operate. All further operations use the management script directly:

```sh
manage_file="${working_dir}/${instance}.manage.sh"
```

---

### 10. Download the Server Files

Fetch and download the server files. Pass a specific version string or use `--latest` to resolve the current latest version automatically:

```sh
version=$("$manage_file" --version --latest)
"$manage_file" --download "$version"
```

---

### 11. Deploy the Server Files

```sh
"$manage_file" --deploy
```

This moves the downloaded files from the temporary directory into the installation directory.

---

### 12. Save the Installed Version

```sh
"$manage_file" --version --save "$version"
```

This records the installed version number for future reference and update checks.

---

### 13. Done!

Your game server instance is now ready. To learn how to start, stop, and manage your new instance, see [Managing Game Servers](managing_game_servers.md).

---

## Best Practices

- **Use Defaults Where Possible**: Setting `default_install_directory` in `config.ini` simplifies the process.
- **Test Each Step**: If creating instances manually, test commands for errors before proceeding.
- **Use `--help`**: All modules support the `--help` flag to list available arguments and descriptions.
- **Read Related Documentation**: See [Instances 101](instances.md) for information about instance structure and [Managing Game Servers](managing_game_servers.md) for day-to-day operations.

## Troubleshooting

### Common Issues

| **Issue**                                 | **Resolution**                                              |
| ----------------------------------------- | ----------------------------------------------------------- |
| Missing installation directory            | Set `default_install_directory` in `config.ini` or provide `--install-dir`. |
| Blueprint not found                       | Run `./kgsm.sh blueprints list` to confirm the blueprint name. |
| Permission errors with `ufw`              | Run the script with `sudo`.                                 |

### Debugging

Use the `--debug` flag for detailed logs:

```sh
./kgsm.sh --debug install <blueprint>
```

Or set the environment variable before running:

```sh
export KGSM_DEBUG=true
./kgsm.sh install <blueprint>
```

### Advanced Integration

For monitoring server creation and lifecycle events programmatically, see [KGSM Event System](events.md) documentation.
