# Project Zomboid server configuration reference

Project Zomboid keeps its settings in three places, and knowing which one a knob lives in is most of
the work:

| Where | Holds | Read |
|---|---|---|
| `saves/Server/<servername>.ini` | ~144 server settings — networking, access, mods, backups, PVP | At startup; some reloadable |
| `saves/Server/<servername>_SandboxVars.lua` | The world: zombie population, loot, day length, difficulty | At world creation, and on start |
| The instance's `executable_arguments` | Launch-only arguments KGSM passes | At launch |

`<servername>` is the instance's `level_name`, which KGSM passes as `-servername`. On a default
instance that is `default`, giving `saves/Server/default.ini`.

## The .ini documents itself

Every setting in the file carries a comment above it, and most state their bounds:

```ini
# Ping limit, in milliseconds, before a player is kicked from the server. (Set to 0 to disable) Min: 0 Max: 2147483647 Default: 0
PingLimit=0
```

Read the file before reaching for any external list — it is generated by the build you are actually
running, so it is never out of date the way a wiki table is. The tables below cover the settings that
matter most for operating a server, not all 144.

## Changing a setting

The file is read at **startup**, so the general procedure is edit and restart:

```bash
kgsm restart my-pz
kgsm instances status my-pz
```

Two console commands avoid the restart:

```bash
kgsm instances input my-pz "showoptions"                    # print current values
kgsm instances input my-pz "changeoption PVP \"true\""      # change one, live
kgsm instances input my-pz "reloadoptions"                  # re-read the file and push to clients
```

`changeoption` alters the running server; `reloadoptions` re-reads the file from disk. Not every
setting takes effect this way — anything consumed once at startup, such as the ports, still needs a
restart.

## Identity and visibility

| Setting | Meaning |
|---|---|
| `PublicName` | The name shown in the server browser |
| `PublicDescription` | The blurb beside it |
| `Public` | Lists the server in the in-game browser. Steam-enabled servers appear in the Steam browser regardless |
| `ServerWelcomeMessage` | Shown in chat on login. `<LINE>` inserts a line break; `<RGB:1,0,0>` colours the text |
| `MaxPlayers` | Player cap. The file's own comment warns that **above 32 risks map streaming problems and desync** |
| `PingLimit` | Kick above this round-trip in milliseconds; `0` disables |

## Passwords, and which is which

Three different passwords, easy to confuse:

| Setting | Guards |
|---|---|
| `Password` | Joining the server at all. Empty means anyone who can reach it can join |
| `RCONPassword` | The remote console. Empty **disables RCON entirely**. The instance carries its own `rcon_password`, and the two must agree — KGSM's copy is what polls, this one is what the server accepts |
| — | The **admin account** password is not in this file. It is set once when the account is created, from `-adminpassword` or the interactive prompt, and changed with the `setpassword` command |

A fresh server ships with `Password` and `RCONPassword` both empty.

## Accounts and access

| Setting | Meaning |
|---|---|
| `Open` | `true` lets anyone join and creates their account on first connect. `false` makes it a whitelist — an admin must create each account with `adduser` |
| `MaxAccountsPerUser` | How many characters one Steam user may create; `0` is unlimited |
| `DoLuaChecksum` | Kick clients whose game files do not match the server's |
| `DenyLoginOnOverloadedServer` | Refuse logins while the server is struggling |
| `SteamVAC` | Enable Valve anti-cheat |

Accounts live in `saves/db/<servername>.db` and each carries a role. The roles, in ascending order:

| Role | What it can do |
|---|---|
| `banned` | Cannot log in |
| `user` | Nothing special — the default for a new player |
| `priority` | Gets login priority |
| `observer` | Teleport, god mode, enter safehouses; cannot grant items or XP |
| `gm` | Everything `observer` can, plus items, XP and world changes |
| `moderator` | Everything except editing roles, reloading Lua, and changing server options |
| `admin` | Everything |

```bash
kgsm instances input my-pz "adduser \"PlayerName\" \"password\""
kgsm instances input my-pz "setaccesslevel \"PlayerName\" \"moderator\""
kgsm instances input my-pz "setpassword \"PlayerName\" \"newpassword\""
```

Bans come in three independent flavours, and lifting one does not lift another:

```bash
kgsm instances input my-pz "banuser \"PlayerName\" -r \"reason\""   # by account; add -ip to also ban the address
kgsm instances input my-pz "banid 76561198000000000"                # by Steam ID
kgsm instances input my-pz "banip 203.0.113.4"                      # by address
```

`unbanuser`, `unbanid` and `unbanip` are their counterparts. KGSM's `kgsm instances ban` and
`unban` verbs use the account form.

## Networking

These are the **game's** settings, in `saves/Server/<servername>.ini`. The instance's own
`<instance>.config.ini` separately declares `ports` and `enable_port_forwarding`, which is what KGSM
opens and forwards — the two describe the same ports from different sides and have to agree.

| Setting | Meaning |
|---|---|
| `DefaultPort` | The main game port |
| `UDPPort` | The second port, used alongside it |
| `UPnP` | Ask the router to forward the ports automatically |
| `server_browser_announced_ip` | The address to advertise, for hosts with several |
| `MaxPacketsPerSecond` | Per-client packet ceiling |

**Project Zomboid is UDP only, and it needs both ports.** A ready server binds `DefaultPort` and
`UDPPort` as two UDP listeners; the blueprint declares the range so KGSM opens and closes it around
the instance's lifecycle. Change a port here and the declared range no longer matches, producing a
server nobody can reach.

**Turn `UPnP` off on a KGSM host.** It defaults to `true`, and KGSM has its own port forwarding
(`enable_port_forwarding` on the instance, driven by the watchdog) which opens the forward on start
and closes it on stop. Two systems creating and removing the same router mapping is how a forward
ends up deleted while the server is still running.

## Mods

Two settings in the server `.ini` — `saves/Server/<servername>.ini`, **not** KGSM's own
`<instance>.config.ini` — both required, holding **different identifiers**:

| Setting | Takes | Where the value comes from |
|---|---|---|
| `WorkshopItems` | Workshop **item IDs** to download | The numeric ID in the Steam Workshop page URL |
| `Mods` | Mod **loading IDs** to enable | The `id=` line in the mod's `info.txt` |

Both are semicolon-separated. Listing a mod in `WorkshopItems` alone downloads it and leaves it
switched off; listing it in `Mods` alone enables a mod that was never downloaded, and the server
fails to find it. This asymmetry is the single most common mod problem.

```ini
WorkshopItems=2503622437;2463499011
Mods=SkillRecoveryJournal;AutoKeyRing
```

`Map` selects the map folder, for mods that ship one. `checkModsNeedUpdate` is a console command that
writes to the log whether any installed mod has a newer Workshop version.

Downloads land in `install/steamapps/workshop/content/108600/<id>/`.

## Saving and backups

| Setting | Meaning |
|---|---|
| `SaveWorldEveryMinutes` | Autosave interval in real minutes. `0` — the default — means the world is written only as clients leave a loaded area |
| `BackupsCount` | How many of the game's own backups to keep |
| `BackupsOnStart` | Take one on every startup |
| `BackupsOnVersionChange` | Take one when the build changes |
| `BackupsPeriod` | Take one every N minutes; `0` disables |

These live in the game's `saves/Server/<servername>.ini` and govern **Project Zomboid's own** backups,
written to `saves/backups/`. They are not KGSM backups: `kgsm instances backups` does not list them,
and the instance's separate `backup_schedule` and `compress_backups` settings drive a different
mechanism entirely.

`SaveWorldEveryMinutes=0` is worth changing on a server that matters — with the default, a crash can
lose everything since the last time a player walked away from an area.

## World and difficulty

`<servername>_SandboxVars.lua` holds the world settings: zombie population and speed, loot rarity,
day length, erosion, and the rest. It is a Lua table, not an INI file.

Most of it shapes the world **at creation**. Changing it later affects what the running server does
from then on, but does not reshape a world that already exists — and a few values, `Seed` in the
`.ini` among them, do nothing at all unless the world is regenerated. The `.ini` comment for `Seed`
says so directly: *"If you want to change this, put a new value in and delete map_worldgen.bin in
your save directory."*

`ResetID` is the soft-reset marker. Changing it forces every client to create a new character, which
is how a wipe is announced to players rather than a thing to edit casually.

## Safehouses, PVP and factions

Large families of settings, all in the same file and all self-documented:

- `PVP`, `SafetySystem`, `ShowSafety`, `SafetyToggleTimer`, `PVPMeleeDamageModifier`,
  `PVPFirearmDamageModifier` — whether and how players can hurt each other. With `SafetySystem=true`
  a player can only be hurt while they have deliberately entered PVP mode.
- `PlayerSafehouse`, `AdminSafehouse`, `SafehouseAllowLoot`, `SafehouseDaySurvivedToClaim`,
  `SafeHouseRemovalTime` — who may claim a safehouse and what it protects.
- `Faction`, `FactionDaySurvivedToCreate`, `FactionPlayersRequiredForTag` — player groups.
- `AntiCheat*` — twelve independent anti-cheat checks, each a severity level rather than a switch.

## Logging

| Setting | Meaning |
|---|---|
| `ClientCommandFilter` | Semicolon-separated commands to keep out of `cmd.txt`. `-vehicle.*` excludes a family, `+vehicle.fixPart` re-includes one |
| `ClientActionLogs` | Which client actions to record |
| `PerkLogs` | Record XP and perk changes |
| `PVPLogToolChat`, `PVPLogToolFile` | Where PVP incidents are reported |

Output goes to `saves/Logs/`, split by kind and by session.
